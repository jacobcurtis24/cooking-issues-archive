### Decisions
- File naming `<audio_dir>/<episode_id>.<ext>`; ext from the enclosure type (audio/mpeg mp3; audio/x-m4a, audio/mp4 m4a), else the URL suffix, else mp3. `.part` (plus a `.part.json` sidecar with total/ETag/Last-Modified) while downloading.
- Always start from the stored `enclosure_url`, follow redirects on every (re)start, never persist/log the resolved URL. `Accept-Encoding: identity`, `iter_raw`, so byte counts equal Content-Length. Timeouts connect 15 s / read 60 s. Retries (max 5, 2/4/8/16/32 s, `Retry-After` honoured up to 300 s) for 5xx/429/timeouts/resets; the retry budget resets whenever the .part grows past its previous best (so a flaky link finishes, a stuck server gives up). 4xx other than 416 are permanent. Resume sends `Range` plus `If-Range` (ETag/Last-Modified from the sidecar); a 200 (Range ignored/validator changed), a 206 with a different start or total, or a 416 on a stale/oversized .part restarts clean (at most 3 restarts). A 416 whose total equals the .part size means "already complete" and goes straight to verification. Shared `HttpClient` throttle keeps it at <= 2 requests/s. Non-audio content types (anything but audio/*, application/octet-stream, binary/octet-stream) fail without retry.
- Verification before the atomic rename: size == Content-Range total / full-200 Content-Length (skipped if the server gives neither, then a full ffmpeg decode is required instead, because Xing/Info headers state the full duration even for truncated files, and size-based ffprobe estimates only catch gross truncation); ffprobe must find an audio stream with positive duration within `max(duration_tolerance_s=120, duration_tolerance_pct=5%)` of `meta.duration_s` (skipped when unknown). Verification failures delete the .part, record `episodes.error`, leave stage `discovered` (a failed `--redownload` keeps the old file and stage `downloaded`, error recorded). Transient give-up keeps the .part for the next run. Then fsync, `os.replace`, fsync of the directory, state update (sha256 computed after verification).
- Adoption: an existing final file that state does not know is adopted after ffprobe + duration check + a `Range: bytes=0-0` probe; nothing is read from the body, the file is only read. If the sizes differ the file is adopted only when the duration matches the feed to within min(5 s, 0.5%) AND a full decode reaches the end (see "Real-world surprise"). Downloaded + file present = skip with no network at all (`--verify` re-checks size, stored sha256 (backfilled when NULL), ffprobe; it makes one Range probe and only notes a changed remote size).
- Source switch: state `downloaded` and `audio_source != audio_downloaded_from` (Patreon copy appeared later) logs an info line and keeps the file; `--redownload` fetches to .part, verifies, then replaces atomically (old file kept until the new one verifies) and updates `audio_downloaded_from`.
- Disk guard: `download.min_free_gb` (default 20, GiB) checked before the first request; after headers also free >= 2x the real size. Failure is `fatal` for the batch (stops it; every later episode would fail the same way). The lock exits with code 3.
- Selection: a selector is required (no selector: usage error, exit 2). `--latest N` = the N newest episodes (within `--source`), with already-downloaded ones skipped when processed. This deliberately differs from "N newest not-yet-downloaded": that reading makes a second `--latest 3` fetch the next three episodes, contradicting "a second run does nothing" (the task's done-when). `--since`/`--all` select only not-yet-downloaded episodes; `--episode` takes ids as given (unknown ids are an error, exit 1); `--source patreon` means "audio comes from Patreon"; `--redownload`/`--verify` include downloaded episodes. Output: one line per episode (live byte/speed line only on a TTY), final summary, exit 1 if anything failed.
- Alerts: `feeds.alert_status` stores the unhealthy status an alert was last sent for. Only `auth` (401/403) and `empty` are alerted, once per status change; `ok`/`not-modified` after an alert sends one "recovered" note; transient `error` neither alerts nor resets. If the push was not delivered (no topic, network down) nothing is recorded, so it is retried at the next poll. Patreon alert text states that polling falls back to the public Acast/HRN feeds. Priority high for alerts. `send_ntfy` never raises, redacts title/body/exceptions (the topic is a secret), logs and returns False without a topic.

### Correction pass (`src/ciw/correct.py`)
Rules in priority order; the first that applies at a position wins:
1. `alias` (conf 1.0, no similarity test): `heard => correct` matches 1-4 adjacent words, case-insensitive, never across punctuation or a pause >= 0.75 s.
2. `merge` (0.98): 2-3 words whose letters concatenate exactly to a term ("poly dextrose" -> polydextrose, "tan door" -> tandoor, "Paco jet" -> Pacojet). Only into a term that is not an everyday word.
3. `normalize` (0.95) / `case` (0.99): the words already are the term with other apostrophes or capitals ("Seattle Ultrasonic's" -> "Seattle Ultrasonics", "cooking issues" -> "Cooking Issues"); case only for terms spelled with a capital and not a single everyday word (so "jack" stays).
4. `fuzzy-merge` / `fuzzy`: Damerau-Levenshtein ratio AND metaphone similarity, confidence = 0.4 x ratio + 0.6 x phonetic >= `asr.correct_min_confidence` (0.86). Fuzzy single: word >= 5 letters, ratio >= 0.70, phonetic >= 0.75, same first sound. Fuzzy merge: ratio >= 0.84, must beat each word's own ratio by 0.1, at least one uncommon word, term >= 7 letters.
- Guard rails (fuzzy only): terms must be >= 7 letters, no digits; a word that already is a term is never touched; an extension of a term or of the word ("pokers", "tandoori", "hydrocolloid is", "Matt Sartwell of") is a different word, never a mis-hearing (a doubled last letter, "Pacojett", is the one exception); two equally good terms mean no change; an everyday English word changes only if it is one edit away from a term of >= 7 letters that appears in this episode's show notes; merges never span punctuation, a lone symbol, or a pause. Never changes a transcript with no vocabulary, and "prefer a missed fix" is the design.
- Audit and idempotency: `Transcript.corrections` (index, original, corrected, start, end, rule, confidence, term, original_words) and `Transcript.correction_hash`; `Word.orig` is written only on words that changed (a custom serializer drops `orig: null`, so transcript.json does not grow). Merged words take the start of the first and end of the last word and the first word's speaker. Applying reverts earlier corrections first and then works on the ASR's own words, so a second run (or a run after editing vocabulary/aliases) equals a fresh pass; tested byte-for-byte.
- Wiring: `ciw transcribe` runs it after the backend (`asr.correct: true`, `--no-correct`), stores `vocab_hash/correction_hash/corrections` in state (migration 4) and prints the number of corrections; `ciw vocab correct EPISODE... | --all [--dry-run | --revert | --transcript PATH | --min-confidence]` works on an existing transcript.json without ASR (atomic write; updates state); `ciw vocab corrections EPISODE [--json]` dumps the audit list.

### Quality check (`ciw vocab quality EPISODE... [--aggregate] [--json] [--transcript PATH]`, also `ciw transcribe --quality`)
Per episode it names the vocabulary terms that the show notes (title + description) mention, then reports: **term recall** (term appears at least once; case-insensitive, whole token/phrase; plural/possessive ok; hyphen = space, and a hyphenated vocabulary term also matches its closed form; "poly dextrose" is not "polydextrose"), the missed terms and what they were heard as, **mention recall** (exact mentions / exact + suspects, where a suspect is a near-miss word or phrase that is not an everyday word: this exposes "Soxhlet right 3 times and wrong 5", which term recall hides), all of it before and after correction (before = the ASR's own words restored from `original_words`), ASR runtime and real-time factor, and a **silent-gap warning** (>= 10 s with no words: dropped audio). `--aggregate` pools episodes; `--json` is complete.

### Stale policy
`ciw transcribe` now compares `Transcript.vocab_hash` (hash of the Whisper prompt actually used; the backend/Transcriber has `vocab_hash()`) with the current one: a different prompt is `STALE` (reported; redone by `--stale` or `--force`), including prompt -> none and none -> prompt. With `vocabulary_prompt: false` the prompt is always none, so editing `vocabulary.txt`/`aliases.txt` never triggers a re-transcription; it only makes the corrections out of date. `ciw episodes list` has a `vocab` column (`-` not transcribed, `ok`, `STALE` prompt differs, `recorrect` vocabulary/aliases/rules changed since the correction pass, fix with `ciw vocab correct --all`) and `--stale` shows only those two (applied before `--limit`). ### Search index (`search_db`, default `data/search.sqlite`; `ciw/search_index.py`)
- Config key `search_db` (guarded by the test-safety guard). Never touches `cooking_issues.db`. Rebuildable: `ciw index --rebuild` builds `search.sqlite.new` beside the old one and swaps it in.
- Schema v1: `utterances_fts` FTS5(`text` indexed; `episode_id, utt_idx, start_s, end_s, speaker` UNINDEXED), `episodes_fts` FTS5(`title, notes` indexed; `episode_id` UNINDEXED), both `tokenize='unicode61 remove_diacritics 2'`, `prefix='2 3 4'`; `indexed(episode_id PK, transcript_sig, transcript_sha1, notes_hash, has_transcript, n_utterances, first_rowid, notes_rowid, indexed_at)`. Utterance rows of an episode have contiguous rowids (`first_rowid .. +n-1`), so replacing/deleting an episode is a rowid-range delete (a `DELETE ... WHERE episode_id=?` on an UNINDEXED column would scan the table).
- Incremental: a transcript is re-indexed only if size+mtime_ns changed AND the content sha1 differs (a `touch` is refreshed without re-indexing); show notes by hash of title+notes; rows of deleted transcripts and of episodes that left the state DB are removed; a bad transcript is an error line, old rows stay, the run continues.
- Utterances = `ciw.transcript.split_utterances` (pause > 1.5 s / speaker change / sentence end after 15 s as before, plus a cut of anything over 50 words after the last sentence end in the second half of the window, else at a real pause >= 0.2 s, else at 50). The transcript page uses the same function, so `utt_idx` is the page's `#u<idx>` and a hit lands on the right block. Indexed text is the corrected words (`Word.w`).
- CLI: `ciw index [--episode ID]... [--all] [--rebuild]` (no selector = `--all`; unchanged episodes are skipped). `ciw transcribe` (episode modes) and `ciw vocab correct` (non-dry-run) call `search_index.index_best_effort`: prints `search index: ...` only if something changed, and a failure prints a warning and never fails the command (tested). `ciw index` needs the state DB.
- Web: state and index are opened read-only (`state.connect_readonly` is new); a missing/corrupt/foreign index gives one-line notices ("run `ciw index`"), never an error.

### Related posts (`ciw/related.py`)
No LLM. Key terms = vocabulary terms present in the title/show notes/transcript, weight `(1 + ln(1+tf)) * ln(1 + N/df) * (1.5 title | 1.25 notes)` (tf = transcript mentions; df = blog posts matching the term as an FTS5 phrase with prefix on the last word); dropped if df = 0 or df/N > 0.4, and (episode page) if the term is in > 30% of all episodes' notes ("Cooking Issues"); fewer than 3 survivors -> capitalised phrases from title/notes fill up under the same weighting; best 8 kept. ### Decisions
- Separate index file with explicit rowid ranges (fast replace) instead of a content table; transcripts and notes in two FTS tables.
- Episode page highlights `?q=` server-side (testable, works without JS) and the find box/Next/Prev are client-side; one component handles both.
- `status=downloaded` means "has audio" (includes transcribed); `transcribed` = stage transcribed or later.
- Episode search results are AND-of-prefix like the blog; boilerplate terms are skipped using the index itself, not a hard-coded stop list.
- `split_utterances` is a new function (the original `utterances`/`render` are untouched, so `transcript.txt` and prompts are unchanged); `silent_gaps`/`GAP_S` moved to `ciw/transcript.py` and `quality.py` now uses them (same behaviour).
- Added `{% block head %}` to `base.html` (an empty line in the output of every page) for the episode stylesheet; the post page uses a scoped inline `<style>` inside the mentions box so its HTML stays identical when there are none.

### Known limitations / open issues
- Only 3 transcripts exist, so episode search/related-by-transcript are exercised on 3 episodes; the other 691 appear through show notes only. Scale untested beyond synthetic runs (index size ~1 MB per transcript; `"a"*`-style prefix queries on 700 transcripts are the thing to watch).
- No speaker labels yet (`diarization_skipped: no_hf_token`); the page prints speaker names when they exist but that path is only unit-tested.
- Search does not match across utterance boundaries (a phrase split by a pause is not found as a phrase); the original ASR wording is not indexed (searching "poly dextrose" finds nothing if it was corrected).
- The first word of a transcript may be missing and the opening is lowercase/unpunctuated (ASR behaviour, shown as is). No gap markers appeared in ep 1 (0 gaps >= 10 s); synthetic tests cover the marker.
- Related posts are only as good as the vocabulary: an episode with no vocabulary terms and no capitalised phrases found in the blog shows "No related posts found". Terms match by prefix in FTS but plurals only by +s/es in the "matched" list.
- Autoplay: click-to-seek calls `play()`, which a browser may block until the user has interacted with the page (a click normally counts). Deep links never autoplay.
- The existing blog oddities (`/browse?page=abc` 500, `/search?q=!!!` inline error, snippets of blog text marked safe) are untouched, as instructed.
